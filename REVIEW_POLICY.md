## 1. Risk Levels

Every task modification must be classified into one of the following risk levels:

| Level | Description | Human Review Required |
|-------|-------------|----------------------|
| **readonly** | Read-only operations — no file modifications | No |
| **low** | Cosmetic changes, documentation, comments, formatting | No |
| **medium** | Scoped logic changes within existing files | Conditional |
| **high** | Schema changes, auth, security, permissions, data deletion | Yes |
| **milestone** | Release sign-off, architecture change, cross-cutting change | Yes (multi-tool) |

## 2. Automation Rules

| Risk Level | Auto-Execute | Auto-Test | Auto-Review | Max Auto-Rework |
|------------|:---:|:---:|:---:|:---:|

| **milestone** | ❌ Must be manual | ✅ | ❌ Multi-tool review required | 0 |

### 2.1 Automated Gate Rules

1. **Low-risk** tasks may be executed, tested, and reviewed fully by AI tools. If tests fail, the AI may retry up to **2 times** before escalating to a human.
2. **Medium-risk** tasks may be executed, tested, and reviewed fully by AI tools, but with stricter oversight. If tests fail, the AI may retry **1 time** before escalating to a human.
3. **High-risk** tasks **must not** be executed or reviewed by AI alone. A human must review the plan before execution and the result after execution.
4. **Milestone-level** changes require a **comprehensive multi-tool review**: Codex + Claude/Cursor/ChatGPT must all independently review the change before sign-off.
5. **Default rules:**
   - AI tools **must not** `git push` automatically under any risk level.
   - AI tools **must not** `git merge main` automatically under any risk level.

### 2.2 Auto-Rework Rules

- After each auto-rework attempt, the AI must run the full test suite again.
- If tests still fail after the maximum allowed rework attempts, the task must be escalated to a human.
- The AI must document each rework attempt and its outcome in the task notes.
- Rework must not expand the scope of the original task.

## 3. High-Risk Task Examples

The following types of changes are **always classified as high-risk** (or higher):

- **Authentication** — Login, logout, session management, OAuth, JWT
- **Authorization / Permissions** — Role-based access control, policy enforcement
- **Database schema changes** — Migrations, column additions/removals, index changes
- **Policy changes** — Security policies, data retention policies, compliance policies
- **Audit-related changes** — Audit logging, audit trail modifications
- **Automated command execution** — Scripts that execute shell commands, CI/CD pipelines
- **GitHub token / API key handling** — Any operation involving tokens or secrets
- **Data deletion** — DELETE operations, data purging, batch removals
- **Production deployment** — Deploy scripts, environment configuration, release processes
- **Payment / billing logic** — Any change affecting financial transactions
- **PII / sensitive data handling** — Changes to how personal data is collected, stored, or transmitted

If a task involves **any** of the above, it must be flagged as **high** or **milestone** risk and requires human review before any code is written.

## 4. Risk Re-classification

A task's risk level may be re-classified during review:

- If a **low** task touches files outside its scope → escalate to **medium**
- If a **medium** task touches security or data-related code → escalate to **high**
- If a **high** task has broad cross-cutting impact → escalate to **milestone**
- Risk de-escalation requires explicit approval from a human reviewer
