## 4. Aider Usage Boundaries

### 4.1 When Aider IS Suitable

Aider + DeepSeek is appropriate **only** when **all** of the following conditions are met:

- **Risk level**: `low` or explicitly vetted `medium` only
- **Scope**: Small, well-defined, limited to **1–2 files**
- **File list**: Complete, explicit file paths are known **before** starting
- **Task type**: Bug fix, minor documentation update, small config tweak, simple test addition
- **No side effects**: The change does not touch security, permissions, database, production config, or CI/CD

> Aider launch recommendation: always start with explicit file arguments, e.g. `aider --file src/foo.py --file src/bar.py`.

### 4.2 When NOT to Use Aider

Aider + DeepSeek must **not** be used in the following scenarios:

- **File scope is unclear** — Aider works best when the exact files to modify are known in advance
- **Multi-file complex tasks** — Tasks involving 3+ files or cross-cutting changes
- **High-risk or milestone tasks** — Authentication, permissions, database schema, policy, audit, production deployment, automatic command execution, payment logic, data deletion
- **Approval or audit workflows** — Aider must not make decisions about who can approve or audit changes
- **Database migrations** — Schema changes require human review and multi-tool validation
- **When the AI tool requests creating files with unusual names or files outside the allowed scope** — This is a red flag that the AI misidentified the task boundaries; stop and re-plan
- **When the task description uses broad authorization** (e.g., "modify anything needed", "you decide files", "fix all related files")

### 4.3 Scope Ambiguity Handling

If the task's file scope is **not clearly defined**, follow this escalation path:

1. **Do not** give the task directly to Aider.
2. Use **ChatGPT** or **Zoo Code Architect** to plan the task first — identify all files that need to change.
3. Once the file list is explicit and approved by a human, the implementation may proceed with the appropriate tool.

### 4.4 Default Fallback

When in doubt, default to **Zoo Code + DeepSeek**.

## 5. When to Escalate to Human or Advanced Review

The following situations **always require** escalation to a human reviewer or multi-tool advanced review:

- **High-risk tasks** — See [`REVIEW_POLICY.md`](REVIEW_POLICY.md) for the full classification
- **Milestone-level changes** — Release sign-off, architecture changes
- **Production deployment** — Any change that affects live services
- **Data deletion** — Any operation that removes data
- **GitHub token / API key handling** — Any operation involving secrets or credentials
- **Automatic command execution** — Scripts that run shell commands, CI/CD modifications
- **Schema migrations** — Database schema changes

---

## 6. Default Prohibitions

The following operations are **prohibited by default** and require explicit human approval:

- `git push` to any branch
- `git merge main` or any branch merge
- Modifying `.env`, `.env.*`, or any file containing secrets, tokens, or API keys
- Modifying real production configuration files
- Running destructive commands (`rm -rf`, `git reset --hard`, `git clean -fd`) without confirmation
