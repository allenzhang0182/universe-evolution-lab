# `.ai/tasks/` — Static Task Directory

> Auto-generated by [`ai-dev-toolkit`](..) — AI SOP v2 template.
> Copy this directory to your target project's `.ai/tasks/` to provide AI tools with
> scoped, single-task instructions.

---

## Purpose

`.ai/tasks/` is a **static task-slip directory**, not a dynamic task scheduler or
execution engine. Each file in this directory is a self-contained task description
that an AI tool (ChatGPT, Zoo Code, Aider, OpenHands, SWE-agent, etc.) can read
and execute.

Key principles:

1. **Static only** — Task files are plain Markdown with YAML front matter (or
   structured sections). No dynamic scheduling, priority queue, or workflow engine.
2. **Temporary by nature** — Task files are meant to be consumed once. Whether
   they are retained or deleted after completion is at the discretion of the
   project maintainer.
3. **Portable** — Any AI tool that can read Markdown can use these tasks.
   No proprietary format or runtime required.

---

## Required Fields

Every task file **must** include the following:

| Field                 | Description                                                           |
|-----------------------|-----------------------------------------------------------------------|
| Task ID               | Unique identifier (e.g., `T-001`, `T-002`)                            |
| Title                 | Short, descriptive title                                               |
| Risk Level            | `readonly` / `low` / `medium` / `high` / `milestone`                  |
| Recommended Tool      | Which AI tool should handle this task                                  |
| Background            | Why this task exists                                                   |
| Goal                  | What the task must achieve                                             |
| Allowed Files         | Glob patterns or paths the AI may modify                               |
| Forbidden Files       | Glob patterns or paths the AI must not touch                           |
| Requirements          | Specific constraints and rules                                         |
| Acceptance Criteria   | Measurable criteria to mark the task as done                           |
| Test Commands         | Commands to verify correctness                                         |
| Review Requirements   | Who or what must review the output                                     |
| Stop Conditions       | Conditions under which the AI must stop and ask for help                |
| Completion Report     | Structured summary the AI must output after finishing                   |

---

## Security Rules

1. **Never** write secrets, tokens, API keys, or real production configuration
   into task files.
2. **Never** allow AI tools to `git push` automatically.
3. **Never** allow AI tools to `git merge main` automatically.
4. **High-risk tasks** (`high`, `milestone`) require human review before
   merging or deploying.
5. If a task encounters a situation outside its defined scope, the AI must
   **stop and ask** for human guidance.

---

## Lifecycle

1. **Create** — A maintainer or AI creates a task file in `.ai/tasks/`.
2. **Execute** — An AI tool reads the file and performs the work.
3. **Review** — The output is reviewed per the task's review requirements.
4. **Clean up** — The maintainer decides whether to keep or delete the task file.
